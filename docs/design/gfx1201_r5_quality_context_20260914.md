# R5 context-qualified quality evaluation — preparation

This document records the fixed input and scoring contract for the additional
R5 quality evaluation. It is a preparation record; no model response was
generated by this commit. The earlier 308-case stop, the HumanEval/129 format
observation, the strict Math-ratio failure, and the 32K TTFT result remain
historical results and are not rewritten by this evaluation.

## Fixed judging and coverage contract

The repaired interactive HumanEval judge is used. Its known correct, known
incorrect, and syntax-error controls must pass before generation. Raw answers
and extracted sources are both retained; no fence closing, return insertion,
answer repair, selective regeneration, or case exclusion is allowed.

The diagnostic hook remains benchmark-only and changes no attention arithmetic,
input contract, KV layout, or production dispatch. It records per-request
`cached_len`/`q_len` shapes, layers, and whether an applied candidate chunk
overlaps the stored problem interval. All 308 candidate requests must have a
positive application count, and at least one applied chunk must overlap the
problem body. Baseline application counts must be zero while target shapes
match candidate shape-by-shape.

Results are classified independently:

1. Correctness uses all cases, including output-limit stops.
2. `finish_reason=length` is counted as truncation and is never repaired or
   removed from the denominator.
3. Syntax/answer-extraction format is compared only for pairs that stopped
   normally on both arms. Raw Markdown violations are recorded separately.
4. New generation errors, empty output, or non-finite returned log probability
   fail the run. Greedy token mismatch alone is not a failure.

The fixed paired gate requires per-task correctness not to decrease, truncation
not to increase, completed-pair format invalidity not to increase, no new
errors/empty/non-finite result, and complete 308-case candidate coverage. Only
if that gate passes may the separately frozen 32K needle/content-retention
experiment run; decode regression, prefix reuse, soak, and production adoption
remain out of scope.

## Environment and commit boundary

The existing R5 environment remains fixed: TP1, K8/V4, MTP2, adaptive
verification disabled, fused MXFP4 decode enabled, compilation mode 0,
`FULL_DECODE_ONLY`, chunk budget 256, `max_num_seqs=1`, one model process,
RAM at most 16 GiB, swap disabled, no profiler, and disk-backed artifacts.
The previous quality artifacts are not overwritten. This preparation commit
freezes the suite and checks; the response/evaluation artifact is a separate
later commit.
